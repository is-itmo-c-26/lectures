# Примеры к лекции 9

Сборка из корня репозитория:

```sh
cmake -S examples/09-operator-overloading -B /tmp/itmo-lecture-09-build -DCMAKE_CXX_COMPILER=clang++
cmake --build /tmp/itmo-lecture-09-build
ctest --test-dir /tmp/itmo-lecture-09-build --output-on-failure
/tmp/itmo-lecture-09-build/rational-input-use
```

Все программы используют C++20 и флаги `-Wall -Wextra -pedantic`. Исключение — `implicit-float-error.cpp`: он намеренно не компилируется и не входит в сборку CMake. Файлы с реализациями отдельных методов связываются с клиентами через библиотеки CMake. `validation.cpp` проверяет ошибки ввода, границы представления дробей, сложение, сравнение, инкремент и запрет копирования владельцев ресурсов.

## Rational

`rational.hpp` продолжает модель из лекции 8: сокращённая дробь, положительный знаменатель и представление нуля `0/1`. Нормализация находится в локальном `normalize-rational.hpp`, чтобы примеры лекции собирались независимо. Если нормализованное значение не помещается в два `int`, конструктор выбрасывает `std::overflow_error`; нулевой знаменатель вызывает `std::invalid_argument`.

Операторы реализованы в отдельных `.cpp`, а преобразование во `float` определено прямо в классе в `rational.hpp`. Объявления свободных функций находятся в `rational-io.hpp`, `rational-comparison.hpp` и `rational-addition.hpp`. Явное копирующее присваивание нужно только для демонстрации; для этих полей хватило бы `= default`. Поэлементное присваивание этих двух `int` корректно и при самоприсваивании.

`operator+` принимает левый операнд по значению и использует `operator+=`. Вспомогательная функция `add_rationals` вычисляет сумму в `long long`, сокращает её до проверки границ `int` и возвращает готовый `Rational`. При переполнении `operator+=` сохраняет исходное значение; `x += x` также корректен. Свободная функция делает интерфейс `+` симметричным, но не отменяет `explicit` у конструктора: для сложения с целым числом нужно явно создать `Rational` или добавить отдельные перегрузки.

В `operator<` умножение выполняется в `long long`; `static_assert` проверяет достаточную разрядность для произведений значений `int`. `operator++` отклоняет переполнение до изменения числителя. Ввод принимает формат `числитель / знаменатель`, допускает пробелы вокруг `/` и при ошибке оставляет прежнее значение. Разбор читает одну дробь из потока, поэтому последующий текст остаётся для следующей операции. Преобразование во `float` явно и может терять точность.

`friend-rational.hpp` — альтернативное определение `Rational`, используемое только в `friend-use` и `friend-output.cpp`. Основной вариант вывода использует публичные методы и обходится без `friend`; альтернативный показывает прямой доступ к закрытым полям. Не включайте его вместе с `rational.hpp` и не связывайте эти две версии класса в одной программе.

`implicit-float-error.cpp` показывает, что `explicit operator float()` не допускает инициализацию `float value = half;`. В `rational-conversion-use.cpp` то же преобразование явно запрашивается через `static_cast<float>`.

`default-order.cpp` — компилируемый контрпример: `operator<=> = default` сравнивает поля в порядке объявления и ошибочно считает `1/2 < 1/3`. Для дробей нужен порядок по значению. В C++20 `!=` может использовать `operator==`, а отношения порядка — `operator<=>`; вручную написанный `<=>` сам по себе не добавляет `==`. Развёрнутые реализации сравнений в основном `Rational` оставлены для объяснения связи между операторами.

Godbolt-ссылки объединяют клиент, его локальные заголовки и перечисленные в `extra-sources` реализации. Исходные файлы остаются единственным источником кода для слайдов и ссылок.

`rational-three-way.cpp` показывает альтернативную реализацию порядка через `operator<=>`: сравнивает перекрёстные произведения в `long long` и возвращает `std::strong_ordering`. В `rational-three-way-use.cpp` показаны прямой вызов `<=>` и отношения `<` и `>=`. Этот пример не включает `rational-comparison.hpp` и не связывается с библиотекой `rational`, поэтому обычные отношения действительно используют `<=>`, а не прежние отдельные перегрузки. Сравнение на равенство `==` в этот пример не входит. Правила результата: [трёхстороннее сравнение в C++20](https://timsong-cpp.github.io/cppwp/n4861/expr.spaceship).

## Индексирование, функторы и RAII

Файловый пример оставлен как дополнительный материал в исходниках. В слайдах RAII показан на `FooPtr`, чтобы сосредоточиться на операторах `*` и `->`.

`IntArray` хранит элементы в `std::vector`; индекс должен быть меньше размера. Проверки `assert` отключаются при `NDEBUG`. У `Multiplier` произведение должно помещаться в `int`.

`FileDescriptor` владеет открытым `FILE*`. Копирование запрещено, перемещение не реализовано. Преобразование в `FILE*` явно и не передаёт владение: вручную закрывать этот указатель нельзя. Пример чтения не обрабатывает ошибки закрытия; для записи, где важна диагностика сброса буфера, нужен отдельный интерфейс завершения операции. `file-use` читает свой исходник через `__FILE__`; при сборке CMake путь абсолютный, а при ручной сборке из текущего каталога может оказаться относительным.

`FooPtr` принимает единоличное владение объектом, созданным одиночным `new`. Нельзя передавать ему указатель на стек, массив или объект, которым уже владеет другая обёртка. Копирование запрещено, перемещение не реализовано; нулевая обёртка допустима, но разыменовывать её нельзя. Для прикладного кода используйте `std::unique_ptr`.

При переносе исходной презентации исправлены чтение неинициализированных значений при ошибке ввода, целочисленное деление в преобразовании во `float`, смешанная знаковость и переполнение в сравнении, опечатка индекса, а также повторное освобождение ресурсов при неявном копировании обёрток.
