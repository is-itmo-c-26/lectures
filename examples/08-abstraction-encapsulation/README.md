# Примеры к лекции 8

Все примеры используют C++20. Из корня репозитория собрать программы без намеренных ошибок можно так:

```sh
cmake -S examples/08-oop-abstraction-encapsulation -B /tmp/itmo-lecture-08-build -DCMAKE_CXX_COMPILER=clang++
cmake --build /tmp/itmo-lecture-08-build
/tmp/itmo-lecture-08-build/int-array-use
```

В сборке включены `-Wall -Wextra -pedantic`. Каждая программа — отдельная цель CMake с именем исходного файла без `.cpp`.

Стек на структуре разделён на два файла, как в лекции про компиляцию: `plain-stack.hpp` объявляет структуру и функции, `plain-stack.cpp` их определяет. Программа `stack-open` связывается с библиотекой `plain-stack`; для Godbolt оба файла объединяются через `extra-sources`.

Код следует стилю из лекции 1: функции, методы и типы — `PascalCase` (`Push`, `IsEmpty`, `Year`, `Numerator`, `PrintRational`), переменные — `snake_case`, константы — `kPascalCase`. Форматирование — `clang-format --style="{BasedOnStyle: Google, IndentWidth: 4, AccessModifierOffset: -4}"`.

## Сборка отдельного примера

Команды ниже выполняются из этого каталога:

```sh
clang++ -std=c++20 -Wall -Wextra -pedantic stack-client.cpp -o /tmp/stack-client
/tmp/stack-client

clang++ -std=c++20 -Wall -Wextra -pedantic rational-use.cpp -o /tmp/rational-use
/tmp/rational-use
```

`Rational` полностью определён в заголовке: числитель и знаменатель имеют тип `int`. Нормализация вынесена в `normalize-rational.hpp`: дробь сокращается, знак отрицательного знаменателя переносится в числитель, ноль хранится как `0/1`. Нулевой знаменатель вызывает `std::invalid_argument`. Промежуточные вычисления выполняются в `long long`, который здесь должен быть шире `int`; если сокращённую дробь с положительным знаменателем нельзя представить двумя `int`, выбрасывается `std::overflow_error`. Например, `INT_MIN/INT_MIN` превращается в `1/1`, а `INT_MIN/-1` отклоняется.

`implicit-rational.hpp` показывает версию до добавления `explicit`, а `rational.hpp` — после. Это самостоятельные варианты одного класса для разных программ. Не включайте оба заголовка в одну программу.

`constructors/rational.hpp` — отдельная учебная версия с явными реализациями обычного конструктора, копирования и перемещения. Цель `rational-constructors` связывается с библиотекой `rational-constructors-demo`; реализации находятся в `rational-constructor.cpp`, `rational-copy-constructor.cpp` и `rational-move-constructor.cpp`, а копирующее присваивание — в `rational-copy-assignment.cpp`. Методы чтения определены в `rational-methods.cpp`. Конструктор перемещения оставляет источник в корректном состоянии `0/1`. Не смешивайте этот класс с двумя заголовочными версиями.

`int-buffer.hpp` показывает владеющий указатель: конструктор выделяет массив через `new[]`, деструктор освобождает его через `delete[]`. Копирование запрещено. Программа `buffer-lifetime` показывает вызов деструктора при выходе из блока. В `construction-order.cpp` вызываются все специальные функции `GeoPoint` и его полей `Rational`: конструкторы, копирование, перемещение, оба присваивания и деструкторы. Отдельные версии классов находятся в `lifetime/`: каждый конструктор, деструктор и оператор присваивания сам выводит сообщение через `std::cout`, а в `main` остаются только операции с объектами. Сообщения содержат только имя класса и операции: на слайдах вывод размечен стрелками, какому объекту принадлежит строка. Вывод из тела конструктора идёт после создания полей; из тела деструктора — до их уничтожения; из оператора присваивания — до присваивания полям. Не смешивайте эти классы с остальными версиями `Rational`.

`plain-date.hpp` показывает открытое представление: год, месяц, день и согласованный с ними `timestamp`. `create-date.cpp` создаёт такую дату, а `date-open.cpp` демонстрирует нарушение инварианта прямым изменением полей. Цель `date-open` связывается с библиотекой `plain-date`.

`date.hpp` и `date-alternative.hpp` задают одинаковый публичный интерфейс: конструктор, `Set`, `Year`, `Month`, `Day` и `Timestamp`. Первая версия хранит три календарных поля, вторая — только `timestamp_`. Это альтернативные определения одного класса; включать их вместе нельзя.

`date-use` и `date-transaction` связываются с библиотекой `date`: `date-constructor.cpp`, `date-set.cpp`, `date-access.cpp`. Цель `date-alternative-use` использует библиотеку `date-alternative`: `date-alternative.cpp`, `date-alternative-access.cpp`. Клиенты `date-use.cpp` и `date-alternative-use.cpp` отличаются только включённым заголовком.

Обе версии и открытая структура используют библиотеку `date-calendar`: `date-to-timestamp.cpp`, `date-from-timestamp.cpp`. `timestamp` — число секунд от 1970-01-01 00:00 UTC до начала выбранного дня. Поддерживаются григорианские годы от 1 до 9999; даты до 1970 года дают отрицательное значение. Календарные преобразования реализованы через C++20 `std::chrono` в этих исходниках. `FromTimestamp` используется для значений в поддерживаемом диапазоне дат.

`int-array-use` использует библиотеку `int-array`: `int-array-lifetime.cpp`, `int-array-access.cpp`, `int-array-copy.cpp`, `int-array-copy-assignment.cpp`. Реализация независимого копирования разобрана в основном разделе о правиле трёх.

`int-array-move-use` — дополнительная программа вне слайдов. Она использует отдельную библиотеку `moving-int-array`: `move/int-array-storage.cpp`, `int-array-move.cpp`, `int-array-move-assignment.cpp`. В этом варианте класса копирование запрещено, перемещение разрешено. Не смешивайте его с классом из примера независимого копирования.

`stack.hpp` и `stack-vector.hpp` — взаимозаменяемые варианты одного класса, оба допускают не более 10 элементов. Второй заголовок можно подставить вместо первого при сборке клиента; одновременно включать их нельзя.

`construction-order` связывается с библиотекой `object-lifetime`. В `lifetime/rational.hpp` и `lifetime/geo-point.hpp` находятся объявления классов, а определения методов — в `.cpp` того же каталога. Без CMake этот пример можно собрать командой `clang++ -std=c++20 -Wall -Wextra -pedantic construction-order.cpp lifetime/*.cpp -o /tmp/construction-order`. Эти же файлы показаны на слайдах. Для Godbolt они автоматически объединяются в один исходник через `extra-sources` в описании ссылки.

`new-delete.cpp` использует `trace.hpp`: конструктор `Trace` печатает `+ имя`, деструктор — `- имя`. Так видно, что `new` и `delete` вызывают специальные функции, а `std::malloc` и `std::free` — нет.

Остальные программы из CMake собираются из одного `.cpp` с локальными заголовками.

## Примеры с намеренными ошибками

Эти файлы исключены из обычной сборки:

| Файл | Причина ошибки |
|---|---|
| `private-access-error.cpp` | Обращение к закрытому полю стека |
| `const-method-error.cpp` | Изменение обычного поля в `const`-методе |
| `missing-default-error.cpp` | Нет конструктора без аргументов |
| `default-delete-error.cpp` | Вызов удалённого конструктора копирования массива |
| `explicit-conversion-error.cpp` | Неявное преобразование через `explicit`-конструктор |

Диагностику можно получить без компоновки:

```sh
clang++ -std=c++20 -Wall -Wextra -pedantic -fsyntax-only private-access-error.cpp
```

`shallow-copy.cpp` и `shallow-assignment.cpp` компилируются, но **запускать их нельзя**: два объекта освобождают один массив. Присваивание также теряет старый массив получателя. Они тоже исключены из CMake.

`stack-open.cpp`, `date-open.cpp` и `date-setters.cpp` намеренно создают логически неверное состояние, но только печатают значения и не выполняют недопустимых обращений к памяти. `date-setters.cpp` показывает, что закрытые поля и сеттеры без проверки сами по себе не сохраняют инвариант даты.

В обеих реализациях стека и во всех вариантах `IntArray` проверки `assert` не заменяют обработку неверного ввода: при `NDEBUG` они отключены. Клиент должен соблюдать предусловия операций. Версия массива с `std::vector` в `array-value.hpp` сохраняет ту же договорённость для `at`, что и ручная реализация.
