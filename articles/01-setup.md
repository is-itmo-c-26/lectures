Чтобы писать, собирать, запускать и сдавать лабораторные, нужно поставить несколько инструментов. Ниже — что это за инструменты, затем установка редактора, а в конце ссылки на гайды под конкретную систему.

## Инструменты курса

| Инструмент | Зачем нужен |
|---|---|
| **Clang** | компилятор, которым собираются лабораторные. Им же собирает CI курса, поэтому локально удобнее иметь тот же компилятор |
| **CMake** | описание сборки проекта: какие файлы компилировать, что с чем линковать, какие тесты запускать |
| **Git** | контроль версий. Все лабораторные сдаются через ветки и pull request'ы, так что без него не обойтись |
| **VS Code** | редактор, в котором вы всё это пишете |

Отдельно ставить ничего больше не нужно: GoogleTest, на котором написаны тесты лабораторных, CMake скачивает сам при первой сборке.

Clang и CMake — не единственный возможный выбор. Есть GCC и MSVC, есть CLion и Visual Studio. Гайды ниже описывают вариант, на который настроен курс; если вы уверенно пользуетесь другим — пользуйтесь, но проверяйте, что ваш код собирается тем же Clang, что и в CI.

## Установка VS Code

Скачать редактор: <https://code.visualstudio.com/download>.

Дальше вам понадобятся расширения. Чтобы поставить расширение, тыкаем на кубики слева на экране и в поиске ищем нужное:

![Панель расширений в VS Code: кнопка Extensions на левой панели и поиск по расширениям](../assets/articles/01-setup/vscode-extensions-panel.png){fig-alt="Окно VS Code с открытой панелью Extensions и строкой поиска"}

Для C++ пригодятся вот эти:

- **C/C++ Extension Pack** — подсветка, переход к определению, отладка;
- **CMake** и **CMake Tools** — поддержка CMake: конфигурация, сборка и запуск прямо из редактора.

![Расширения C/C++ Extension Pack, CMake и CMake Tools в списке установленных](../assets/articles/01-setup/recommended-extensions.png){fig-alt="Список установленных расширений VS Code: C/C++ Extension Pack, CMake и CMake Tools"}

> Ставить расширения можно и позже — сначала имеет смысл разобраться с компилятором. Если вы на Windows и будете работать через WSL, расширения для C++ удобнее ставить уже после подключения к WSL: VS Code разделяет расширения на локальные и те, что живут внутри WSL.
